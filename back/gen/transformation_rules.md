**Independent validation notes**

- `lb:Artist`, `lb:Medium`, and `lb:Track_psi_track_01` provide class mappings with pivot relations and URI templates, so they yield CTRs. The Track number mapping uses the same `track` pivot and URI constructor; its class association is supplied by `lb:Track_psi_track_01`.
- The Artist name, GUID, sort label, Medium title, Medium track count, and Track number values are attributes of their respective pivots and therefore yield Local DTRs. The Track number rule retains the SQL selection condition `track.position IS NOT NULL`.
- Artist annotation and gender values come from relations joined to the Artist pivot, so they are Path DTRs. The gender path has a supplied FK name. The annotation path is structurally present in the query, but the metadata does not supply a named FK for `artist_annotation.annotation → annotation.id`.
- `lb:artist_dbpedia` emits an IRI-valued `owl:sameAs` object from a related URL. It does not provide a subject-map definition for `lb:sm_artist`, nor a target-class CTR for the URL resource. Consequently, this mapping can be represented as an OTR-shaped external-IRI rule, but it cannot be validated as a framework-conforming entity-preserving OTR from the supplied information.
- The missing `lb:sm_artist` definition prevents independent confirmation of the subject URI constructor for the annotation, gender, and DBpedia mappings. Their pivot and relational paths are recoverable from the supplied logical tables, but the subject URI component remains unresolved.
- The DBpedia logical-table SQL contains `INNER JOIN link_type ON link_type = link_type.id`. The metadata describes a path through `link_type`, but does not resolve that SQL join expression into an independently validated FK traversal. Only `l_artist_url_fk_entity0` is supplied as a matching FK name.
